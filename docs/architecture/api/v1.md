# Freequademy API v1 — contract

Base URL: `https://api.freequademy.com` (staging: `https://api-staging.freequademy.com`). Until the gateway is live, the same routes are reachable at `https://<project-ref>.supabase.co/functions/v1/api/v1/…`.

**Conventions (all endpoints)**

- **Request ID:** send `x-request-id` (8–64 chars `[A-Za-z0-9._-]`) or one is generated. Always returned in the `x-request-id` response header and in error bodies; it is also stored with audit-log and job rows.
- **Errors:** `{"error": {"code": "<snake_case>", "message": "<user-safe text>", "request_id": "…"}}`. No stack traces or internal messages, ever.
- **Auth:** `Authorization: Bearer <Supabase access token>`. The function verifies the token, then queries with the caller's own JWT, so Postgres RLS is the final authority.
- **Simple data access is not duplicated here.** Owner-scoped CRUD stays on Supabase's Data API (`/rest/v1/…`, `/auth/v1/…`, `/storage/v1/…`), which the gateway forwards unchanged.

| Method · path | Auth · role | Request | Response 200 | Errors | Rate limit | Cache | Database | Side effects |
|---|---|---|---|---|---|---|---|---|
| `GET /v1/health` | none | — | `{status:"ok", request_id}` | — | gateway IP limit | none | none | none |
| `GET /v1/public/subjects?class_level=6..12` | none | query `class_level` | `{data:[{id,name,slug,class_level,sort_order}]}` | `400 invalid_request`, `500 internal` | gateway IP limit | `public, max-age=300`; gateway caches 60 s for anonymous callers only | `subjects` select (RLS: public read) | none |
| `GET /v1/student/dashboard?class_level&from&to` | JWT · any signed-in user (own data only) | `class_level` 6–12, `from`/`to` `YYYY-MM-DD`, range ≤ 366 days | `{data:{summary,subjects,xp_breakdown,weak_areas,recent_tests,weekly_summary,mentorship,activity_days,continue_lesson,doubt_stats,recent_doubts}}`; each section is `{data}` or `{error:"<SQLSTATE>"}` | `401 unauthorized`, `400 invalid_request`, `500 internal` | gateway per-IP | `private, no-store` | `get_student_dashboard()` (SECURITY INVOKER; per-section definer RPCs scoped to `auth.uid()`) | none |
| `POST /v1/ai/doubts` | JWT · any signed-in user | `{question (1–2000), subject?, grade? 6–12, image? data-URL ≤5 MB}` | `{data:{answer, doubt_id, remaining, model}}` | `400 invalid_request`, `401 unauthorized`, `429 ai_quota_exhausted` (+`remaining:0`), `429 ai_rate_limited`, `502 ai_unavailable`, `503 ai_not_configured`, `504 ai_timeout`, `500 internal` | 30 per user per day (`consume_ai_quota`) + gateway | `private, no-store` | `consume_ai_quota()`, insert `doubts` (RLS: own row) | calls the configured AI provider chain (primary → fallback), 30 s timeout, 1 retry each |

**Legacy endpoint kept for the current web client:** `POST /functions/v1/doubt-solver`, same workflow, response `{answer, doubtId, remaining}` / `{error}`.

**Internal (not public):** `POST /functions/v1/worker` — requires `x-worker-secret`; called by pg_cron. Claims `webhook` jobs through service-role-only RPCs (`jobs_claim/complete/fail`).

**Versioning:** breaking changes go to `/v2`; `/v1` keeps working until every client (web, future Android) has moved. Additive fields are not breaking.
